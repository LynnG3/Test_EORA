## Ключевые возможности проекта

### Что реализовано
✅ **AI-ассистент с возможностью отвечать на вопросы клиентов** на основе контента с сайта

✅ **Автоматический веб-скрапинг сайта eora.ru** с извлечением всех ссылок на кейсы

✅ **Векторное хранилище FAISS** для эффективного поиска релевантного контекста

✅ **Гибридная система AI моделей:**
   - **HuggingFace** - локальная модель question-answering для генерации ответов
   - **OpenAI GPT-3.5-turbo** - опциональное использование для улучшенного качества ответов
   - **Автоматический fallback** - при недоступности OpenAI автоматически переключается на локальную модель
✅ **Оптимизированные embeddings** - всегда используются локальные HuggingFace embeddings для экономии API вызовов
✅ **HTTP API с FastAPI** для программного взаимодействия

✅ **Веб-интерфейс** - простой чат-виджет для пользователей

✅ **Автоматическое обновление данных** при запуске приложения

✅ **Система сессий** для отслеживания истории чатов

✅ **Умная обработка ошибок** - пользователю показываются понятные сообщения, технические детали остаются в логах

### Что пробовала сделать

🔄 **OpenAI API** - изначально планировала использовать GPT, но столкнулась с ограничениями по региону и квотам

�� **Различные модели HuggingFace** - экспериментировала с TinyLlama, GPT-2, DialoGPT, в итоге остановилась на DeBERTa для question-answering

🔄 **Ollama** - рассматривала как альтернативу, но модель оказалась слишком тяжелой (4GB)

🔄 **Google Gemini API** - недоступен без VPN

#### ✅ Сработало хорошо:
- **Веб-скрапинг** - успешно извлекает контент с eora.ru
- **Векторный поиск** - быстро находит релевантный контекст
- **Автоматизация** - скрипты запускаются при старте приложения
- **Гибридная система** - автоматический fallback между OpenAI и локальной моделью
- **Обработка ошибок** - система gracefully обрабатывает сбои API

#### ❌ Проблемы:
- **Качество ответов HuggingFace** - модель извлекает слишком короткие фрагменты
- **Ограничения DeBERTa** - максимум 512 токенов контекста
- **Низкие confidence scores** - модель часто не уверена в ответах
- **OpenAI лимиты** - даже новые аккаунты имеют ограничения по запросам

### Оценка качества решения

**Сильные стороны:**
- Возможность автономной работы без внешних API
- Автоматическое обновление данных
- Современная архитектура с FastAPI
- Надежная система fallback - приложение работает даже при сбоях внешних сервисов
- Правильная обработка ошибок - пользователь не видит технические детали

**Области для улучшения:**
- Качество и полнота ответов локальной модели
- Обработка длинных текстов
- Улучшение точности модели

### Что бы добавила при наличии времени

1. **Поиск оптимальной модели** - переход на более мощную модель с поддержкой русского языка
2. **Предобработка текста** - очистка и структурирование спарсенного контента
3. **Кэширование** - сохранение результатов для повторных запросов
5. **Тестирование** - unit и integration тесты
6. **Документация API** - Swagger/OpenAPI спецификация
8. **Аналитика качества** - сравнение ответов разных моделей

### Сложности и найденные решения

1. **Блокировка сайта (403 ошибки)** → Добавила User-Agent заголовки и задержки
2. **Импорты и пути** → Решила через sys.path и правильную структуру проекта
3. **Ограничения модели** → Адаптировали под question-answering pipeline
4. **Циклические импорты** → Вынесла зависимости в отдельный модуль
5. **Ошибки OpenAI API** → Реализовала автоматический fallback на локальную модель
6. **Технические детали ошибок в UI** → Разделила логирование и пользовательские сообщения

### Безопасность

- **Валидация входных данных** через Pydantic модели
- **CORS настройки** для веб-интерфейса
- **Логирование** всех основных операций
- **Обработка ошибок** без раскрытия внутренней информации в чате
- **Локальная модель** - данные не покидают сервер
- **Автоматический fallback** - система остается работоспособной даже при сбоях внешних сервисов

## Запуск проекта

### Режим разработки

1. Клонирование и настройка:
```
git clone https://github.com/LynnG3/Test_EORA.git
```
```
cd Test_EORA-1
```
```
python -m venv venv
```
```
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate     # Windows
```

2. Установка зависимостей:
```
pip install -r requirements.txt
```

3. Запуск:
```
cd eora_ai_assistant
python run.py
```

Приложение будет доступно по адресу: http://localhost:8000

### Сборка и запуск в Docker

```
docker-compose up --build
```
или
```
docker compose up --build
```

## Основные технологии

1. Backend  
- Python 3.11 - основной язык разработки
- FastAPI - веб-фреймворк с асинхронностью
- Uvicorn - ASGI сервер для FastAPI  

2. AI и ML  
- HuggingFace Transformers - библиотека для работы с моделями
- Open_AI - - интеграция с GPT-3.5-turbo для генерации ответов
- DeBERTa - модель для question-answering
- FAISS - векторное хранилище для поиска
- Sentence Transformers - эмбеддинги для текста  

3. Веб-технологии  
- HTML5/CSS3 - веб-интерфейс
- JavaScript - интерактивность чата
- AJAX - асинхронные запросы к API  

4. Инфраструктура  
- LangChain - интеграция с AI моделями
- BeautifulSoup - парсинг HTML
- Requests - HTTP клиент
- Pydantic - валидация данных
